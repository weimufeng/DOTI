# DOTA2 本命英雄测试 App：阶段 1 需求基线

**版本：** v0.1  
**日期：** 2026-08-06  
**状态：** 待产品负责人确认后冻结

## 1. 产品定义

面向中文 DOTA2 玩家及泛游戏用户的移动端优先网页测试。用户完成 3–5 分钟的题目后，获得一张可分享的“本命英雄”结果：英雄、MBTI、九型人格、匹配原因及相近英雄。

本产品是娱乐型人格测试，不提供心理诊断、医学建议或经验证的 MBTI/九型人格测评结论。

## 2. 已确认背景与时间约束

- 项目文档提出以 2026 年 TI 上海热度作为传播机会。
- Valve 的 TI 2026 售票公告称，上海现场活动为 **2026 年 8 月 20–23 日**；项目文档中的“8 月 13 日开赛”不作为发布日期依据。
- 推荐的公开 MVP 日期：**8 月 18 日前**，为活动开始预留两天观察、修正和内容预热。
- 英雄池、平衡性和赛事信息均会变化；首发数据必须保存版本与采集日期，不能把“128 位英雄”写死为永久事实。

## 3. 目标、非目标与成功标准

### 目标

1. 让用户快速得到有 DOTA2 代入感、愿意转发的英雄人格结果。
2. 让结果具备可解释性：用户能理解答案如何导向人格与英雄。
3. 建立可维护的英雄、人格、题目和文案内容库。

### MVP 范围边界

- 不承诺临床有效性或官方 MBTI/九型人格认证。
- 不在 MVP 中制作原生 iOS/Android App；以响应式 Web App 承载。
- 不依赖未经授权的自动抓取、复制或再分发第三方人格数据库。

账号、好友关系、排行榜和第三方授权**允许纳入 MVP**，用于提升分享与社交传播；是否实现以首发时间、隐私合规和所需授权能力评估为准。若实现，必须采用显式授权、最小权限、可撤销连接与清晰的删除/退出机制。不得将用户的 Steam 或社交账号数据用于人格结论，除非另行取得明确同意并完成独立的产品与隐私评审。

### 首发指标（需在上线前确认数值）

| 指标 | 初始目标 | 口径 |
| --- | ---: | --- |
| 开始答题→完成答题率 | >= 65% | 完成页访问 / 首题作答 |
| 答题中位时长 | 3–5 分钟 | 首题作答至提交 |
| 结果页分享率 | >= 15% | 分享操作 / 完成答题 |
| 结果满意度 | >= 70% | “像我/能接受”正向反馈占比 |
| 致命错误 | 0 | 阻塞答题、无法生成结果或分享 |

## 4. 目标用户与核心场景

| 用户 | 需求 | 典型入口 |
| --- | --- | --- |
| 核心 DOTA2 玩家 | 想知道自己像哪位英雄，并识别赛事/游戏彩蛋 | 社群、战队或赛事内容 |
| 轻度玩家/观赛者 | 想以低门槛方式参与 TI 话题 | 社媒分享卡、朋友链接 |
| 非玩家 | 想完成有游戏主题的人格测试 | 社媒结果页 |

核心路径：落地页 → 开始测试 → 24–32 题 → 提交 → 结果页 → 保存/分享 → 可选重测。

## 5. MVP 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-01 | 落地页说明测试时长、娱乐性质和隐私提示 | Must | 用户可在开始前看到三项信息 |
| FR-02 | 支持 24–32 道单选题、进度、返回修改与中断恢复 | Must | 刷新页面后不丢失未提交答案 |
| FR-03 | 按 MBTI、九型人格和英雄向量计算结果 | Must | 相同答案始终返回相同结果；无空结果 |
| FR-04 | 结果展示英雄、人格标签、匹配说明、相近英雄 | Must | 每个可返回英雄均有完整中文内容 |
| FR-05 | 生成移动端可读的分享卡和可复制结果链接 | Must | 主流手机浏览器可保存/复制；链接可复现结果 |
| FR-06 | 记录匿名漏斗与分享事件 | Should | 可按渠道查看开始、完成和分享数据 |
| FR-07 | 内容可通过结构化文件或后台更新 | Should | 非前端开发者可修改题目、文案和权重 |
| FR-08 | 反馈“像/不像我”与自由文本 | Could | 反馈与结果 ID 关联，不收集身份信息 |
| FR-09 | 可选账号登录与匿名结果绑定 | Should | 未登录也可完成测试；用户可查看、删除或解除绑定自己的结果 |
| FR-10 | 可选好友关系、结果比较或邀请 | Could | 仅在双方或受邀方主动操作后显示；不默认公开测试结果 |
| FR-11 | 可选第三方账号授权 | Could | 授权范围、用途、撤销入口清楚可见；授权失败不影响核心测试 |

## 6. 内容与体验原则

- **所有题目都必须与 DOTA2 直接相关**：可引用游戏对局、英雄、物品、地图、赛事、选手、历史或社区文化，相关程度可不同，但不得存在脱离 DOTA2 的通用人格题。
- **每道题都必须影响人格结论**：每个选项须映射到至少一个 MBTI 维度或九型人格动机，并在计分规则中具有非零权重；不得设置只为彩蛋、却不参与结论的题目。
- DOTA2 语境服务于人格测量，而非玩家知识测验：陌生术语须提供简短解释；“不知道/不玩”不应被计为某种人格倾向。
- 题目避免性别、地域、段位或战绩刻板印象，不将攻击性、成瘾或消极情绪包装成褒贬人格。
- 结果文案使用“你的回答更接近”“匹配度较高”等概率语言。
- 每个结果显示“仅供娱乐，不构成心理评估”。

## 7. 隐私、版权与合规边界

- 默认可匿名答题；登录、绑定结果、好友关系与第三方授权均为可选功能。
- 对账号、好友或第三方授权数据，采用最小权限、用途告知、显式同意、可撤销和可删除原则；授权失败或拒绝不得阻碍核心测试。
- 仅保留实现分析和已授权社交功能必需的最小化数据，并在落地页说明用途与保存期。
- 英雄名称、图像、商标、赛事影像及第三方人格资料必须记录来源与许可状态；未经确认时使用自制抽象视觉或官方允许的素材。
- PDB 是候选参考源，非默认可抓取数据源。开始任何自动采集前，必须由负责人核验其条款、robots 规则、访问限制及再利用许可。

## 8. 待决策事项（阻塞后续阶段）

1. 首发语言是否仅简体中文，及是否需要英文结果页。
2. 目标部署域名、预算、分析平台和隐私政策主体。
3. DOTA2 视觉素材的授权路径；未获授权时是否接受自制风格化结果卡。
4. 人格数据库的数据来源、许可、负责人及人工审核流程。
5. 首发英雄范围：全英雄完整内容，还是“全英雄可匹配 + 热门英雄深度文案”。
6. 对非 DOTA2 用户的处理方式：是否限制为 DOTA2 玩家使用，或在题干内提供必要术语说明（不改变题目全 DOTA2 化的原则）。
